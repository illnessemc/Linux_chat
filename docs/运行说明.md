# 部署与运行说明

本说明面向首次取得源码的使用者。项目运行于Linux或WSL2，客户端经TCP连接C服务，C服务调用本机常驻vLLM与Qwen 4B。C服务只监听回环地址，不提供登录、远程访问、TLS或跨启动恢复历史。

## 一 环境检查

本机已验证Ubuntu 22.04、Python 3.10、GCC 11.4、vLLM 0.11.2、Torch 2.9.0及RTX 4060 Laptop 8GB。固定依赖见`config/requirements-vllm.txt`，不建议在复现过程中任意升级。

在Linux中执行`nvidia-smi`，确认驱动可用并有足够空闲显存。Windows用户应先保证WSL2可以访问GPU。模型启动脚本按本机验证配置使用AWQ、FP16和FLASH_ATTN；不兼容的GPU不能通过改用终端客户端解决推理问题。其他硬件需要自行验证支持情况与显存预算。

将源码放在Linux可读写目录，不要求使用原作者的用户名或桌面路径。例如克隆后进入`Linux_chat`目录，后续构建、C服务和客户端命令均在项目根目录执行。

## 二 首次准备

```bash
sudo apt update
sudo apt install build-essential pkg-config libcurl4-openssl-dev libjson-c-dev python3-venv curl

# 只在使用桌面客户端时安装
sudo apt install python3-tk fonts-noto-cjk

# 安装推理环境并检查CUDA可用性
bash scripts/setup_vllm.sh

# 下载固定修订的模型文件并校验SHA-256
python3 scripts/download_model.py

# 编译C服务端与终端客户端
make
```

安装脚本在用户目录新建虚拟环境，不覆盖系统Python。默认环境是`~/.local/share/linux-chat/venv`，模型目录为`~/.local/share/linux-chat/models/Qwen3-4B-Instruct-2507-AWQ-Eslzzyl`。项目没有默认远程API或免GPU的应用后端。

`config/model.json`固定模型仓库、修订号和文件哈希。下载器默认并发数为4，可用`python3 scripts/download_model.py --jobs 2`调整。中断后重新执行会续传并重新校验；若已有正式文件哈希错误，下载器报错而不覆盖，先保留并检查该文件。所有文件校验成功后生成`download-manifest.json`，启动脚本会检查它是否存在。

如需改运行目录，先在当前终端执行以下命令，再准备环境与模型；后续启动模型的终端也必须设置相同变量：

```bash
export VLLM_RUNTIME_DIR="$HOME/.local/share/my-linux-chat"
bash scripts/setup_vllm.sh
python3 scripts/download_model.py
make run-model
```

单独改变模型位置时，用`python3 scripts/download_model.py --model-dir /绝对路径/模型目录`下载，启动时使用相同的`VLLM_MODEL_DIR`。该变量不会自动改变下载器的默认目录。

## 三 启动与就绪确认

模型服务、C服务和客户端是三个独立程序，分别在终端中保持运行。

```bash
# 终端一
make run-model

# 另一个终端检查，成功时返回包含qwen4b的JSON
curl --noproxy '*' --fail http://127.0.0.1:8000/v1/models

# 终端二
make run

# 终端三
make run-client
# 图形客户端也可用：make run-desktop
```

模型加载需要时间。应以HTTP接口成功响应为就绪标准，不能仅根据进程存在或GPU占用开始提问。`make run`编译后启动C服务，它不会自动下载或启动模型。

构建产物位于`build/bin/server`和`build/bin/client`。终端客户端只有标准输入输出要求；Tkinter桌面需要有效图形显示。`make desktop`只检查Linux、Python和Tkinter，不会创建窗口。

## 四 使用客户端

终端输入问题后回车，回答逐片段显示。输入`/info`查看连接编号、历史轮数及日志位置；`/clear`清空当前连接历史但保留日志；`/quit`或Ctrl+C关闭当前连接。

桌面左侧新建、切换和关闭会话。Enter发送、Shift+Enter换行；“显示”菜单调整字体和字号。用户消息靠右、模型回答靠左，正文可选择复制。停止生成会断开当前连接，点击重连后开启新的服务器上下文；旧界面文字不代表服务器已经恢复历史。

每个桌面窗口最多8个会话，C服务最多32个连接，模型最多同时处理2个请求；额外生成请求会立即收到忙碌提示，不进入C层排队。单个问题最多4096 UTF-8字节。历史最多8轮且16384字节，并按实际token预算裁剪最早完整问答。每轮最多输出1024 tokens，较长回答可能达到上限而结束。

桌面中文显示依赖字体，直接拼音输入还依赖Linux输入法。Windows能输入中文不代表Linux窗口已配置输入法。可使用已配置的Fcitx5/XIM，并在启动窗口前设置`XMODIFIERS=@im=fcitx`；本项目不会安装或改写使用者的shell与输入法配置。未配置时可粘贴中文或先使用终端客户端。

## 五 修改端口与超时

```bash
# 三个独立终端
VLLM_PORT=8001 make run-model
make run PORT=5001 VLLM_URL=http://127.0.0.1:8001 TIMEOUT=120
make run-client PORT=5001
# 或：make run-desktop PORT=5001
```

C服务只接受回环HTTP模型地址。`PORT`为C服务端口，`VLLM_PORT`为模型端口，两者不同。客户端`HOST`默认为127.0.0.1；当前C服务不对局域网或公网开放。模型别名默认为`qwen4b`，修改C侧`MODEL`并不会自动修改启动脚本的模型别名。

## 六 停止与运行文件

先退出客户端，再在C服务终端按Ctrl+C。C服务关闭自己的连接和HTTP请求，等待工作线程清理后退出，不停止共享vLLM。最后在模型终端按Ctrl+C释放模型资源。不要通过结束所有Python或vLLM进程来取消单个会话。

问答、诊断和服务日志位于`logs/run_*/`，会包含提问及回答。记录不与其他连接合并，但应按敏感数据保管。`make clean`移除`build/`，保留源码、模型和日志；模型位于项目外，不应因清理项目而删除。

## 七 常见故障

| 现象 | 检查方法 |
| --- | --- |
| 缺少curl或json-c头文件 | 安装libcurl4-openssl-dev、libjson-c-dev和pkg-config后重新make |
| setup_vllm检查CUDA失败 | 确认Linux中的nvidia-smi和兼容GPU，检查驱动与WSL GPU支持 |
| 提示先安装或下载 | 确认运行目录、venv/bin/vllm及模型download-manifest.json |
| 客户端连接失败 | 检查C服务是否启动，以及双方PORT是否相同 |
| 已连接但生成失败 | 检查8000端口模型接口、VLLM_URL与本会话generator.log |
| 模型启动显存不足 | 检查其他GPU程序占用；当前显存比例为0.60，其他硬件需验证 |
| 模型忙碌 | 等待已有两个请求结束后重试 |
| 桌面提示无显示 | 使用具有WSLg/X11的图形会话，或改用make run-client |
| 模型忘记早期消息 | 检查是否重连、清空、达到历史或token限制 |
| 停C服务后显存未释放 | 独立vLLM仍在运行，需要在它的终端正常退出 |

运行成功可按以下顺序检查：模型列表能返回、C服务可连接、两次连续问答能够完成、`/info`和`/clear`正常、退出客户端后C服务仍可使用。
